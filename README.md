# 人生底层逻辑

> 一份**可以被反驳**的原则清单。35 条原则，每条都写明四件事：**原式**（一句话）、**机制**（为什么成立）、**边界**（什么时候会失效）、**动作**（具体做什么）。

这不是真理清单，是一份**有边界的启发式集合**。它的价值不在任何单条格言，而在**两条原则打架时你按哪条**——那个排序就是你的价值观。

## 这是什么

一份**个人思考的记录与整理**，不是学术论文，也不是方法论。

它试图回答一个问题：**当直觉互相冲突时，按什么排序？**

例如下面这些真实的冲突，文档里都给了裁决方式：

| 两条原则打架时        | 怎么裁                             |
| -------------- | ------------------------------- |
| 课题分离 ↔ 共情与责任   | 看**行动的主语**。感受可以很深，行动必须分清归属      |
| 拒绝外部认同 ↔ 接受反馈  | 看**能否翻译成动作**。能翻译的是信息，不能的是身份评价   |
| 行动先于动机 ↔ 想清楚再动 | 看**可逆性**。可逆 → 先动；不可逆 → 先想       |
| 接纳现状 ↔ 改变现状    | 看**可改变性**。对可改变的认命、对不可改变的较劲，是两种病 |

## 内容结构

```
Part I   作者已说出的四条          ← 文档的原点，其余都是延伸
Layer A  资源层 · 能量与注意力      4 条
Layer B  边界层 · 你与他人          4 条
Layer C  本体层 · 情绪与自我        5 条
Layer D  认知层 · 判断与决策        6 条
Layer E  行动层 · 时间与执行        5 条
Layer F  意义层 · 存在与方向        3 条
Meta     元层 · 关于这套逻辑本身     4 条
仲裁表   9 组常见原则冲突的裁决方式
```

**每条都是统一结构**，不写"要乐观""要专注"这种无法执行的话：

| 字段     | 回答的问题            |
| ------ | ---------------- |
| **原式** | 一句话怎么表述          |
| **机制** | 为什么它成立（因果链，不是断言） |
| **边界** | 什么时候它会失效、会被滥用    |
| **动作** | 具体做什么，通常带一个自问句   |

其中「边界」是这份文档和鸡汤的分界线。比如"你在寻求谁的认同，就是在向谁赋权"这条，滥用会变成拒绝一切反馈——所以它明确写了**如何区分信息性反馈与身份性认可**。

## 如果只记 7 条

35 条会稀释熟练度。压力时刻你只有几秒钟，能想起来的只有最熟的三五条。**先给这 7 条排序——那个顺序就是你的价值观。**

1. **精力要分配，不是靠意志** —— 增源 / 节流 / 按节律调度
2. **你在思考谁的问题，就是在参与谁的因果** —— 停止替别人背负因果
3. **你在寻求谁的认同，就是在向谁赋权** —— 把裁判权收回来
4. **情绪可堪破** —— 它是对解释的反应，不是对事实的反应
5. **行动先于动机** —— 等待动力是效率最高的拖延
6. **系统 > 目标** —— 目标定方向，系统出结果
7. **控制二分法** —— 只在「我能控制的」那一栏花时间

### 配套工具

[`tools/energy-audit.html`](tools/energy-audit.html) 是对「资源层」四条的可执行版本：

- 按小时记录精力档位与精力流向（9 类活动）
- 每天记录 5 个环境维度评分（视觉场 / 归位度 / 数字环境 / 动线摩擦 / 感官负荷）
- 自动生成：24 小时节律曲线、生产流向堆叠图、**环境指数 × 精力散点图**（含相关系数）、精力×流向热力矩阵
- 自动诊断：黄金时段、生理低谷、最大泄漏点、峰值利用率、能量收支比
- 全部数据保存在**浏览器本地**（localStorage），不上传、无后端。支持导入导出 JSON/CSV。

## 本地使用

```bash
git clone https://github.com/moonlit-firefly/life-logic.git
cd life-logic

# 方式一：直接打开
open index.html          # macOS
start index.html         # Windows

# 方式二：起个本地服务器（如果你要测试相对路径）
python3 -m http.server 8000
```

## 部署到 GitHub Pages

1. 把这个仓库推送到 GitHub
2. 进入仓库 **Settings → Pages**
3. **Source** 选 `Deploy from a branch`，**Branch** 选 `main`、目录选 `/ (root)`
4. 保存，等 1–2 分钟，访问 `https://moonlit-firefly.github.io/life-logic/`

根目录的 `index.html` 会被自动识别为首页，`.nojekyll` 保证静态资源不被 Jekyll 处理。
